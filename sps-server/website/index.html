ONE WORKSPACE, MANY MACHINES

대화는 Room에서, 실행은 권한 있는 Node에서.

프로젝트별 장기 Room과 목표별 Task Room을 분리하고, Lead AI가 필요한 Worker에게만 작업을 할당합니다. 실제 실행은 승인된 컴퓨터에서만 일어납니다.

01

역할과 Room

Designer, CTO, Manager, Worker처럼 역할별 장기 대화 공간을 만들고 작업의 맥락을 프로젝트 안에 유지합니다.

02

목표별 Task

Lead가 작업 목표와 완료 기준을 담은 Task Room을 만들고, 담당 Worker가 결과와 막힌 이유를 같은 흐름 안에 남깁니다.

03

실제 데스크톱 실행

초대된 사람의 PC는 SPS Desktop Node로 연결됩니다. 각 Node는 자신의 Codex CLI, 로컬 모델, 전문 도구만 사용합니다.

HOW SPS WORKS

사람과 AI가 같은 작업 흐름을 봅니다.

SPS는 단순 채팅 도구가 아닙니다. 설계, 할당, 실행, 보고를 명확한 경계로 연결해 작은 팀도 반복 가능한 제작 흐름을 가질 수 있게 합니다.

  1. 1

    프로젝트와 역할을 만든다

    공통 운영 규칙과 역할별 지침을 설정하고, 프로젝트 Room을 준비합니다.

  2. 2

    Lead가 목표를 Task로 분해한다

    Lead AI가 필요한 결과물, 담당자, 충돌 주의 파일을 포함해 Task를 만듭니다.

  3. 3

    승인된 Node가 실행한다

    Owner가 허용한 Agent-Node 조합만 해당 컴퓨터의 CLI나 로컬 AI를 실행할 수 있습니다.

  4. 4

    결과는 Room으로 돌아온다

    완료, 검토 대기, 권한 문제 같은 상태가 Task와 상위 Room에 남아 다음 결정을 돕습니다.

LOCAL-FIRST AUTHORITY

권한은 중앙에서 관리하고, 민감한 실행 환경은 각 PC에 둡니다.

Hub는 회사, 초대, Task, Node 승인과 Agent 권한을 관리합니다. 반면 CLI 로그인 정보, 로컬 모델 파일, 작업 폴더는 해당 Node의 컴퓨터 밖으로 전송하지 않습니다.

  • Google 로그인신원 확인과 초대 수락
  • 일회용 초대 코드회사 접근 권한 부여
  • Node 승인새 컴퓨터는 Owner 승인 전까지 대기
  • Agent별 실행 권한컴퓨터와 AI 역할을 조합해 최소 권한 적용
