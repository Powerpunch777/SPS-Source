# SPS 설계 기준과 문서 적용 순서

갱신: 2026-11-02. 사용자 요청에 따른 설계 문서 정렬이다.
코드 변경, 장기목표 재개, 기능 완료 또는 배포 승인이 아니다.

후속 사용자 승인으로 [Builder 선행 실행 계획](BUILDER-PREREQUISITES-EXECUTION-PLAN-2026-11-02.md)을
저장하고 장기목표를 등록했다. 위 중단/문서 전용 범위는 앞선 정렬 단계의 기록이며,
이후 사용자가 목표를 일시중지하고 범위를 정리한 뒤, 첫 목표를 Builder 완성으로 바꾸고
필요한 안전 기반부터 구현을 재개하라고 지시했다. 최신 실행 순서는
[Builder 우선 계획](BUILDER-FIRST-IMPLEMENTATION-PLAN-2026-11-02.md)을 따른다.
최신 결정은 [현재 작업 범위](CURRENT-WORK-SCOPE-2026-11-02.md)를 따른다. 자체 LAN과
Preview 및 Marketplace 개발·추가 시험은 보류한다. 독립 설정·복구는 Core 필수 기능으로 유지한다.
이 설계 기준의 장기 목표와 과거 완료 증거는 바꾸지 않으며 구현을 자동 재개하지 않는다.

## 단일 기준

사용자가 제공한 [Core–Plugin 원문](../design/CORE-PLUGIN-ARCHITECTURE-2026-10-25.md)을
제품 목표의 최상위 기준으로 다시 적용한다. ZIP 원문 파일의 SHA-256은
`8e77fb84439ab1f8779cca86bd35cabf2bdee497a706bfa4912f7523e26f9a77`이다.
이 값은 입력 원문의 식별값이며 현재 구현의 검증 해시가 아니다.

적용 순서는 사용자 최신 결정, 위 원문, 이 정렬 문서, 분야별 설계, 구현 계약,
날짜·리비전이 붙은 검증 기록이다. 실제 보안 제약과 지원하지 않는 API를 설계로
우회하지 않는다. README는 이번 수정 범위에서 제외했으며 상충하는 과거 요약은
새 설계의 근거로 사용하지 않는다.

10월 28일 이후의 개인 외주 전용·공개 생태계 철회·OS 격리 제외 정책은
이번 설계 목표를 축소하는 근거로 사용하지 않는다. 과거 실행 범위와 검증 사실은
그대로 보존한다. Core 비공개·SDK 공개는 유지한다. Builder/Preview의 구체적인
라이선스와 저작권·판매·수익 배분은 이번에 확정하지 않는다.

## 공통 규칙

| 영역 | 목표 |
| --- | --- |
| Core | 인증, Workspace, Host/Node, 기술 실행·저장·이벤트·스케줄·기록·생명주기·보안·복구 |
| Plugin | 업무, 프로젝트, 조직·역할, Lead/Worker, 대화·기억, 승인·평가와 화면 |
| 최초 상태 | Agent0, Primary0, Extension0인 빈 Workspace 정상 지원 |
| Primary | Workspace 기본 진입 UI를 선택적으로 제공. 0개 또는 최대1개, 권한 등급 아님 |
| Extension | 여러 개 활성화. 전용 창·전체 화면·헤드리스·일반 SDK 기능 사용 가능 |
| 화면 | Core 상단바·사이드바·Dashboard·Inbox·설정 버튼을 Plugin에 강제로 삽입하지 않음 |
| 시스템 관리 | Plugin 코드 없이 Native 트레이·전역 단축키·독립 Settings, Workspace 전환·복구 제공 |
| 설치와 데이터 | 패키지는 Host1회 설치. 활성화·설정·데이터·실행 정책은 Workspace별 |
| 창과 실행 | 창 닫기와 Core 종료 구분. 다중 Workspace/동일 Workspace 다중 창·백그라운드 |
| 실행 제어 | pause는 신규 차단, stop은 신규 차단과 관리 실행 중단, resume은 신규 허용 |
| 재시작 | pause/stop 영속화. 취소된 작업 자동 재생 금지 |
| 파일 | 최대 접근 범위는 선택 사항. 미설정은 OS 사용자 권한 한도, Source/cwd와 구분 |
| 보호 | 설정된 파일 범위는 Plugin·CLI·스크립트·자식까지 집행. 미지원 경로는 명시 거부 |
| Vault | 전체 파일 허용 여부와 별개로 Core 비밀 원문 보호. DPAPI/Job/API 검사만으로 보장하지 않음 |
| 네트워크 | 기본 자유. 일반 사이트별 allowlist/denylist를 Core 필수 정책으로 만들지 않음 |
| 자원 | Workspace별 관찰, 공유 비용 별도 표시. CPU/RAM 자동 강제 한도는 보류 |
| 업데이트 | 자동 확인/안전한 다운로드와 사용자의 실제 적용 선택을 분리, 호환성·롤백·데이터 보존 |
| 초기화 | 현재 Workspace의 해당 Plugin만 기본 대상. 전체 초기화 별도 확인, 외부 프로젝트 제외 |
| 백업 | Core 관리 Plugin 데이터/설치 상태 보존, 외부 저장소 선택 훅. 인증정보 기본 제외·재연결 목표 |
| 통신과 의존성 | 선택적 기술 계약. 다른 Workspace 접근·의존 설치·활성화에 사용자 허가 필요 |
| 오류 | 로컬 기록 기본. 원격 전송은 동의·최소화·민감정보 제거 후, 거부해도 이용 가능 |
| 제작 | 공개 범용 Builder는 선택형. 다른 Builder·외부 IDE·SDK/CLI 제작도 동등하게 가능 |
| Preview | Builder 전용이 아닌 공통 격리 개발 기능. 실제 Workspace/데이터/설치 승인과 분리 |
| Marketplace | 별도 확장 단계의 목표. 버전/해시별 실제 검사 범위 표시, 절대 안전 보장이나 자동 설치 아님 |

## 구현과 목표를 구분

빈 Workspace, 세션/실행·KV·이벤트·Job·권한·Plugin 생명주기와 독립 복구창 등은
현재 소스에 기반이 있다. 그러나 Plugin 진입 후 강제 Core 프레임, 단일 일반
Workspace 창, 독립 Settings의 전체 관리 기능, OS Vault/파일 격리, 범용
Workspace별 Plugin 초기화·이동·자원 귀속은 추가 작업/검증이 필요하다.

현재 Google 우선 로그인과 Source/cwd/grant는 각각 현행 연결·실행 계약이다.
원문의 로컬 단독·선택형 연결 및 최대 파일 범위 목표가 이미 구현됐다는 뜻이 아니다.
지원 OS/전송 방식·서명·설치·실기기 자격은 실제 후보의 근거로 별도 판정한다.
내장 Native LAN 보류와 Native 시스템 관리 UI는 다른 기능이다.

현재 Host 이동 파일은 SQL snapshot 등의 민감값을 포함할 수 있다.
10월30일 안내 정책과 해당 검증 기록을 과거 사실로 유지하되, 원문의
기본 인증정보 제외·재연결 목표를 충족했다고 표시하지 않는다.

## Builder 정렬

별도 [Builder 저장소](https://github.com/Powerpunch777/SPS-MY-PluginBuilder)의 v15는
범용 Builder 안의 솔루션 제작 워크플로 설계다. 개인 외주 이용은 하나의 적용 사례이지
다른 사용자의 제작이나 다른 Builder를 막는 Core 규칙이 아니다.
Lead3세션·공통 Lead 기억, 프로젝트별 CTO 단일 세션, 독립 Dev/QA,
GitHub Actions/Self-hosted Runner는 해당 Plugin의 선택한 워크플로에만 속한다.
Core 역할·필수 초기 데이터로 옮기지 않는다.

Builder UI v9와 검정·중립 회색 기준은 그 Plugin에만 적용한다. Core 시스템 관리 UI의
라이트 스타일이나 다른 Plugin 테마를 강제하지 않는다. Core 메뉴 없는 전체 Plugin
화면을 목표로 하며, 현재 Core 프레임 안의 시험 통과는 그 목표의 완료 증거가 아니다.

## 문서 보존과 후속 검증

- 현행 설계는 이 기준과 일치하도록 정렬한다.
- upstream Paperclip 명세/과거 계획은 호환성 참고로 보관하고 SPS의 필수 업무 규칙으로 채택하지 않는다.
- 날짜·커밋별 감사·시험·실패 기록은 재작성해 통과로 만들지 않는다.
- 생성된 후보/보안 문서는 실제 매트릭스·정책으로만 생성하며 이번 설계에 맞춰 버전을 바꾸지 않는다.
- README, 실행 코드, DB/마이그레이션, SDK API/manifest, 계정·설치본·DEV 데이터는 변경하지 않는다.
- 설계 정렬 이후 구현은 별도 지시를 기다린다. 장기목표는 자동 재개하지 않는다.
