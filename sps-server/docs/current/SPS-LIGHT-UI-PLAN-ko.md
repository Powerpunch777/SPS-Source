# SPS 라이트 UI 개선 설계

날짜: 2026-10-18
상태: 밝은 테마 방향 확정, 시각 구현 전

## 사용자 결정

- 흰색과 연회색 중심의 밝고 차분한 작업 화면을 먼저 완성한다.
- Codex 라이트의 명확한 작업 영역과 절제된 화면 구성을 참고한다.
- 글꼴, 정보 밀도, 탐색 구조와 패널 구성을 함께 정리한다.
- 이 문서는 이전에 롤백한 OpenDesign 구현을 재적용하는 결정이 아니다.

## 현재 코드에서 확인한 문제

- Core는 InterVariable을 사용하며, 한글용 Pretendard는 fallback 이름만 있고
  글꼴 파일이 번들되어 있지 않다. 한글은 컴퓨터의 설치 글꼴에 의존한다.
- Desktop 로그인/Registry는 별도의 글꼴·색상을 선언한다.
- Builder와 Team Workplane은 system-ui를 직접 지정한다.
- 설정 화면에 설명 영역, 상태 배지, 관리 명령이 반복되어 실제 설정보다
  안내 문구와 테두리의 비중이 크다.
- 기존 Builder 화면은 대화와 작업보다 제작 기록 및 계약 설명을 먼저 보여준다.

## 화면과 책임

Core는 앱 프레임, 탐색, 공통 컨트롤, 글꼴·색상·간격 토큰과 접근성 기준을
제공한다. 플러그인은 업무 화면의 구성과 내용을 소유하고 공통 스타일을
재사용할 수 있어야 한다. Core에 Builder의 Lead/Worker 화면을 넣지 않는다.

앱 프레임은 접고 크기를 조절할 수 있는 왼쪽 탐색, 중앙 작업 영역, 필요할
때 여는 오른쪽 상세 패널로 구성한다. 각 영역은 독립 스크롤을 유지한다.
설정 화면은 항목 목록과 상세 영역을 사용하며, 긴 기술 설명은 펼침 영역에
둔다. 오류 및 복구에 필요한 경로는 계속 접근 가능해야 한다.

Builder는 Lead 대화를 중앙에 놓고, Worker 목록·상태와 파일·변경·검증 결과를
보조 영역에 둔다. 별도 Preview 창은 실제 결과를 확인하는 용도로 유지한다.
Lead 1명과 선택 Worker 구성은 Builder 플러그인 설계를 따른다.

## 구현 순서

1. 글꼴 파일·라이선스, 글자 크기와 공통 색상 토큰을 준비한다.
2. Core의 공통 프레임 및 설정 > 플러그인을 대표 화면으로 완성한다.
3. 실제 앱에서 한·영 혼합, 긴 이름, 좁은 창, 스크롤과 키보드 포커스를 확인한다.
4. 같은 기준을 로그인, 서버 생성·참여, 설정 하위 화면으로 확장한다.
5. Builder의 대화·Worker·결과 화면을 플러그인 내부에서 구현한다.
6. 공통 UI 토큰을 플러그인 제작자가 쓸 수 있게 문서와 SDK 예제에 반영한다.

## 완료 증거

- 실제 앱 캡처에서 기존/변경 화면을 비교할 수 있다.
- 배포 앱에서 한글과 영문에 의도한 로컬 글꼴이 실제 적용된다.
- 1024x720, 1280x800, 1440x900에서 겹침·잘림 없이 사용할 수 있다.
- 메뉴·상세 패널 접기와 크기 조절 후에도 현재 작업과 입력 영역이 유지된다.
- 빈 상태·로딩·오류·선택·비활성 상태가 공통 기준으로 구분된다.
- 기능 제거와 업무 흐름 변경은 시각 정리만으로 결정하지 않는다.
