# 현재 작업 범위와 목표 변경 기록

확정: 2026-11-02, 사용자와 작업 범위를 다시 정리한 시점.

**최신 지시: 첫 목표는 Builder 완성이고, 안전에 필요한 선행 작업부터 구현을 재개한다.**
[Builder 우선 계획](BUILDER-FIRST-IMPLEMENTATION-PLAN-2026-11-02.md)이 아래 중단 기록보다
우선한다. Marketplace·Preview·자체 LAN 보류는 유지한다. 도구의 이전 목표는 교체 기능
제약으로 아직 paused이며, 허위 완료로 처리하지 않았다. DEV 재시작·설치 교체는 별개다.

## 적용 순서

최신 사용자 결정 → [Core 원문](../design/CORE-PLUGIN-ARCHITECTURE-2026-10-25.md) →
[설계 기준](DESIGN-BASELINE-2026-11-02.md) → 이 문서와
[선행 계획](BUILDER-PREREQUISITES-EXECUTION-PLAN-2026-11-02.md)을 적용한다.
과거 계획의 active, 구현 중, 시험 예정 표현은 현재 중단 상태를 해제하지 않는다.
원문에 장기 기능이 있다는 이유만으로 지금 구현할 일로 편입하지 않는다.

## 용어

| 이름 | 의미 | 현재 결정 |
| --- | --- | --- |
| 독립 설정창 | 플러그인 화면이 고장 나도 접근하는 Core 관리·복구 화면 | Core 설계의 필수 기능으로 유지. 현재는 문서만 정리 |
| 자체 LAN | Tailscale 대신 SPS가 직접 제공하려던 원격 연결 | 개발·도입 보류. 기존 Tailscale 유지 |
| Preview | 제작 중인 플러그인이나 생성 결과를 별도 환경에서 실행·확인하는 기능 | 개발·추가 시험 보류. Builder 선행 조건으로 삼지 않음 |
| Marketplace | 플러그인 검색·추천·등록·공유·유통 등을 제공하는 영역 | 관련 개발·추가 시험 보류. Core/Builder 선행 조건으로 삼지 않음 |

앞으로 설명에서 서로 다른 기능을 Native라는 말 하나로 묶지 않는다.

## 앞선 중단 시 정리한 선행 범위

아래는 선행 기반 목록이다. 최신 첫 목표인 전체 Builder 완성을 이 목록만으로 축소하지 않는다.

1. 기존 독립 설정·복구의 빈칸을 확인한다. 플러그인 없음/오류/비활성 상태의 접근,
   비활성화·중단·복구, 영향 범위를 보여주는 초기화 확인 등 원문에 있는 기능에 한정한다.
2. Core의 공통 실행·저장·결과 조회·취소·재시작 복구를 기존 API/SDK로 연결한다.
   중복 요청과 응답 유실을 구분하고, 불확실한 요청을 자동 재전송하지 않는다.
3. 강제 Core 메뉴 없는 선택형 플러그인 화면과 빈 Workspace의 정상 동작을 유지한다.
   플러그인 화면과 무관하게 독립 설정·복구로 들어갈 수 있어야 한다.
4. 별도 [SPS-MY-PluginBuilder](https://github.com/Powerpunch777/SPS-MY-PluginBuilder)
   레포의 통합 설계 v15/UI v9와 최신 UI 적용 기준을 실제 구현 기준으로 따른다.
   Core 문서에서 Builder 업무 구조나 화면을 다시 설계하지 않는다. 공개 SDK로 실제 대화 전송·응답·중단·
   분할 저장·재시작 유지를 연결하고, 이미 기록된 검증을 먼저 활용한다.
5. 실제 실패와 아직 증거가 없는 부분만 선별해서 고친다. 전체 출시 검사를 Builder
   개발의 선행 조건으로 추가하거나 같은 시험을 근거 없이 반복하지 않는다.

독립 설정·복구의 기존 필수 범위를 자체 LAN 보류와 함께 제외하지 않는다.
새로운 제품 정책이나 데이터 삭제 범위가 필요할 때는 사용자에게 먼저 확인한다.

Core 원문은 플랫폼·보안·SDK 경계를 정하고, Builder 레포는 해당 플러그인의 업무와
화면을 정한다. Builder 설계는 단순 참고 예시가 아니며 이 선행 목록만으로 전체 설계를
축소하지 않는다. 다만 최신 사용자 결정인 Marketplace·Preview·자체 LAN 보류는
이전 문서에 관련 작업이 있더라도 우선 적용하며, 설계 원문이나 과거 증거를 삭제하지 않는다.

## 하지 않을 일

- 자체 LAN 개발·연결 전환, Preview 및 Marketplace 개발·추가 시험을 재개하지 않는다.
- Core에 Lead/CTO/Worker, 업무 배정·승인·평가, 기억 전략을 고정하지 않는다.
- CTO·Dev/QA/Runner와 v15 납품 흐름은 Builder 레포 설계대로 진행할 본 목표이며 Core
  선행 기능으로 옮기지 않는다. 코드 서명·실기기 등 Stable 출시 조건은 선행 범위로 확대하지 않는다.
- 미검증 생성 코드나 미지원 보호 경로를 안전하다고 간주해 실행하지 않는다.
  Preview 보류는 기존 보안 검사나 Vault·파일·자식 프로세스 보호 목표의 폐기가 아니다.
- 동의 없이 DEV/설치본/계정/사용자 데이터를 변경하거나 초기화하지 않는다.
- 기존 Preview 코드를 보류 결정만으로 삭제·롤백하거나 설치·활성화하지 않는다.
- 기존 Marketplace 코드도 보류 결정만으로 삭제·롤백하거나 활성화하지 않는다.
- 통과시키기 위해 실패 검사를 건너뛰거나, 원인 확인 없이 제한 시간을 늘리지 않는다.
- 과거 시험, 현재 소스, 설치본, 실제 AI, 실기기 및 출시 자격을 같은 완료로 표시하지 않는다.

## 현재까지 확인된 상태

아래는 [진행 기록](BUILDER-PREREQUISITES-PROGRESS-2026-11-02.md)과
[완료 감사](BUILDER-PREREQUISITES-COMPLETION-AUDIT-2026-11-02.md)에 있는 범위의 요약이다.
이번 문서 정리에서 앱이나 시험을 다시 실행한 것은 아니다.

| 항목 | 기록된 결과 | 남은 구분 |
| --- | --- | --- |
| 선택형 Builder 화면 | Core 강제 프레임 없는 page 앱 검증 | 모든 창·오류·복구 경로 완료 아님 |
| 내구 전송·대화 저장 | Core89/89, 공개 SDK191/191, Builder87/87 및 해당 리비전 앱 기록 | 미출시 SDK source pin. 모든 provider 보장 아님 |

| 원격 CI | db9dd6e run41380878666 실패 | Windows 고정 개수 검사, Linux watchdog timeout, 누락된 installer 입력을 구분 |
| 최신 DEV | 기존 사용자 프로세스·데이터 유지 | 새 소스 적용이나 새 권한 승인 미실시 |

Source의 마지막 로컬 커밋은 `18e6bb87538daa7ed52b1c2306f8d7dc54f75957`이며
중단 시점에 push하지 않았다. 문서 변경도 로컬에 남아 있다. 기존 Preview 변경은
별도 과거 기록이며 현재 재개 범위에 포함하지 않는다.

별도 Linux 진단 시험은 중단됐고 남은 실행 세션이 없다는 보고를 받았지만,
그 시험의 임시 DB 정리는 확인되지 않았다. 재개 후 소유권과 종료 근거부터 확인하며
사용자 데이터나 출처 불명의 임시 폴더를 임의 삭제하지 않는다.

## 재개 기준

사용자가 후속으로 Builder 완성과 선행 구현 재개를 요청했다. 최신 계획을 따른다.
재개할 때 현재 파일·프로세스·실패 증거부터 확인하고 실제 남은 Core 복구 항목을 고른다.
목표 완료는 기존 증거와 남은 필수 항목을 대조한 뒤 판단하며, 보류 기능의 구현으로 대체하지 않는다.
