## Provenance와 통합 조건

- 현재 SDK history lane은 node | agent_session뿐이다. Core Agent-session history는 저장된 ownership snapshot과 receipt-bound usage evidence를 테스트한다. 직접 모델 API나 OCE 제어 작업을 이 두 lane으로 위장하지 말고, 추가 lane/actor/source/runtime provenance가 필요하면 별도 계약으로 정의해야 한다. [Core session ownership 테스트](../../../external/sps-core/server/src/__tests__/plugin-agent-session-context.test.ts#L191), [receipt 검증 테스트](../../../external/sps-core/server/src/__tests__/sps-execution-observation.test.ts#L77), [SDK lane 타입](../../../external/sps-plugin-sdk/runtime/index.d.ts#L31)
- 재사용 우선순위는 Core의 storage/events/jobs, grant 기반 Node dispatch 및 관측, Core Agent adapter/session lifecycle이다. SDK API는 pinned source와 공개 배포 tag의 차이를 release tuple에서 명시적으로 검사해야 한다.
- 구현 착수 전 최소 확인 항목: Host capability/version negotiation, 회사 범위가 고정된 secret broker 계약과 OS trust boundary, 직접 API/OCE를 포함할 execution provenance 모델, Preview를 production execution guarantee와 분리하는 정책.
