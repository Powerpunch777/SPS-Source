# SPS 소스 경계와 제한 베타 피드백

## 결정

SPS는 제품 Core를 공개 소스로 배포하지 않는다. 대신 외부 개발자가 안전하게
확장할 수 있는 연결부만 공개한다.

| 구분 | 공개 여부 | 위치 | 목적 |
| --- | --- | --- | --- |
| Plugin SDK, CLI, package·Registry 계약 | 공개 | `Powerpunch777/sps-plugin-sdk` | 플러그인 작성·검사·서명 규격 |
| Windows 설치 파일과 업데이트 메타데이터 | 공개 | `Powerpunch777/SPS-Desktop-Releases` | 설치 앱의 안정적 업데이트 |
| SPS Core, Desktop, Owner Host, 기본 Memory 구현 | 비공개 예정 | 제품 소스 저장소 | 제품 로직·보안 경계·사용자 데이터 처리 |
| 사용자 프로젝트, Room, Task, Vault, API 키 | 공개 금지 | 각 Owner의 로컬 데이터 | 개인·팀 데이터 보호 |

공개 SDK의 Apache-2.0 라이선스는 SDK 자체와 플러그인 작성 도구에만 적용한다.
SPS, SonParkServer, 로고, 공식 배지, 공식 Registry의 상표·운영 권한은 별도다.

## 기존 공개 코드와 라이선스

현재 제품 저장소에 공개된 과거 커밋은 단순히 레포를 비공개로 바꾼다고 회수되지
않는다. 또한 `external/sps-core`에는 Paperclip의 MIT 라이선스가 적용되는 파생
부분이 있다. 해당 고지와 라이선스 의무는 계속 보존해야 한다.

따라서 제품 소스의 최종 라이선스는 다음 감사를 끝낸 뒤에만 확정한다.

1. 파일별 원저작권자와 제3자 의존성 목록 작성
2. MIT·Apache 등 기존 허용 라이선스의 NOTICE 보존 여부 확인
3. 외부 기여 코드의 사용 권한 확인
4. 제품 고유 코드와 외부 유래 코드를 분리
5. 소프트웨어 라이선스 검토를 거쳐 비공개 제품 약관 또는 source-available
   정책 확정

이 문서는 법률 자문이나 최종 라이선스가 아니다. 그 전에는 공개 코드를 새로운
제한 라이선스로 소급 표기하지 않는다.

## 공개 피드백과 제한 베타

소셜·카카오톡에는 제품 코드 레포 대신 다음만 공유한다.

- 소개 페이지, 기능 영상, 익명화한 화면 캡처
- 피드백 폼 또는 전용 문의 채널
- 필요할 때만 제공하는 서명된 Desktop 설치 파일과 1회성 초대 코드

제한 베타는 실제 운영 회사와 분리된 시험 Company·시험 프로젝트에서 진행한다.
테스터에게는 자신의 Google 계정으로 로그인하게 하고, Owner가 Computer와 Agent
권한을 승인한다. 실제 프로젝트, API 키, Owner Vault, 팀 초대 코드, 운영 서버 URL,
로그 전체를 단체 채팅이나 공개 글에 올리지 않는다.

피드백은 세 종류로 나눈다.

| 종류 | 받는 곳 | 공개해도 되는 정보 |
| --- | --- | --- |
| UX·기능 제안 | 공개 폼 또는 SDK Discussions | 재현 단계, 익명 화면, 기대 동작 |
| 앱 오류 | 제한 베타 문의 채널 | 앱 버전, 시간, 비밀을 제거한 오류 요약 |
| 보안·권한 문제 | 비공개 보안 연락처 | 최소 재현 정보만, 공개 Issue 금지 |

## 비공개 전환 순서

1. `sps-plugin-sdk` 공개 레포와 `SPS-Desktop-Releases` 공개 Release 채널을 유지한다.
2. Desktop `0.4.19` 이상의 **서명된 브리지 업데이트**를 기존 공개 업데이트
   채널로 한 번 배포한다. 이 버전부터 새 Release 채널을 확인한다.
3. 사용 중인 모든 Owner·Member 컴퓨터가 브리지 버전 이상으로 업데이트됐는지
   확인한다.
4. `Powerpunch777/SPS` 제품 소스 레포를 비공개 전환하고, 개발 인원만 초대한다.
5. 새 비공개 제품 소스에서 후속 Desktop Release를 발행한다. 설치 앱은 계속
   공개 `SPS-Desktop-Releases`만 조회한다.

2단계의 정식 Release에는 Windows 서명 인증서와
`SPS_DESKTOP_RELEASES_TOKEN`이 필요하다. 이 토큰은
`Powerpunch777/SPS-Desktop-Releases`에만 Contents 읽기·쓰기를 허용하는
fine-grained token으로 제한한다. 이 두 준비가 없으면 unsigned 파일을 정식 업데이트
채널에 올리지 않는다.

## 완료 기준

- 공개 SDK는 제품 소스 경로와 사용자 데이터를 포함하지 않고 CI를 통과한다.
- 공개 Release 레포는 설치 파일과 `latest.yml`만 제공한다.
- 제품 Core의 라이선스·NOTICE 감사가 끝나기 전에는 비공개 전환을 강행하지 않는다.
- 베타 피드백은 실제 운영 데이터와 분리된 시험 환경에서만 수집한다.
